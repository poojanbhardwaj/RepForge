## Milestone 1 readiness evidence

The implementation selects Auth0 as the OIDC integration target without automating or claiming tenant configuration. Mobile uses native Authorization Code + PKCE, refresh credentials, process-death restoration, terminal-session cleanup, subject-partitioned query caches, and canonical HTTPS API transport (literal loopback HTTP only for development). Web uses Auth0 v4 encrypted HttpOnly stateless sessions and a server-only BFF with fixed upstream routing, exact Origin/Fetch Metadata, strict JSON/idempotency, bounded request/upstream bodies, no-store responses, and refreshed-session cookie propagation.

The Go API accepts deterministic auth only in local/test. OIDC mode strictly validates canonical HTTPS issuer/discovery/JWKS, same-origin JWKS, RS256 key metadata/strength/rotation, signature, issuer, audience, authorized client, expiry, issued-at/not-before, subject, optional verified-email claim, and RFC-compatible scopes. The selected Auth0 API profile is exact RFC 9068: `typ: at+jwt` with `client_id`; the default Auth0 `typ: JWT` / `azp` profile, aliases, mixed client claims, and missing types are rejected. Profile and onboarding routes require explicit read/write scopes. Error/log paths do not expose credentials, headers, bodies, free text, or verifier detail.

Migration `000002_onboarding.sql` adds owner-linked resumable state and an owner-scoped idempotency ledger. First-login provisioning is transactionally serialized by provider/subject. Updates validate bounded enums/ranges/timezones/equipment, distinguish omitted versus explicitly cleared optional diet preference, lock the owner row, and persist an authoritative replay snapshot. Adult/safety evidence timestamps are preserved; legal acceptances record exact versions; presentation and completion re-gate against current configured Terms/Privacy versions. PostgreSQL coverage exercises concurrent first login, identical-request replay, ownership/disabled users, legal re-gating, completion evidence, and migration round trip.

On 2026-08-30 the complete local sequence passed: frozen install, format/generation freshness, lint, typecheck, unit/component/contract tests, PostgreSQL/Redis/object-store integration, Go/Next/Expo builds, security, migration, smoke, and final `verify`. The final gate passed 12 tooling, 3 API-client, 21 web, and 53 mobile tests plus all Go and real-container integration packages. Security reported no unallowlisted working-tree or reachable-history secret, Go vulnerability, gosec finding, or pnpm advisory. Smoke covered profile/onboarding auth, authoritative idempotency replay and conflict, exact CORS, and truthful dirty-tree build metadata. Regardless of those automated results, live Auth0 callbacks, verified-email policy, token permissions, refresh/logout failure paths, emulator/device protected storage/process death, and web cookie behavior still require the sanitized manual runbook. Production tenant administration/MFA, attack protection/rate limiting, Auth0 log retention/export, key/secret rotation, legal/vendor review, native release analysis, DAST, and independent testing remain blockers.
