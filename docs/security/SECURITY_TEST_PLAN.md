# Security test plan

Automation covers literal-loopback environment isolation; fail-closed dev/OIDC modes; OIDC discovery/JWKS/key rotation and claim negatives; duplicate/missing auth and scopes; web session/BFF origin, media, idempotency, body/response bounds, token forwarding, and cookie-refresh cases; onboarding ownership, strict validation, resume/retry, consent re-gating, concurrency and PostgreSQL migration behavior; profile deadline/ownership/concurrency; cache isolation and accessible mobile/web states; route/log redaction; generated contract drift; complete installed-graph dependency auditing; Go SAST/vulnerability checks; digest-pinned working-tree/history secret scans with canaries; immutable image manifests/local-only waivers; explicit missing inventory; and container-boundary smoke with exact build metadata, onboarding replay/conflict, and CORS.

Manual Milestone 1 testing follows the Auth0 runbook and must cover native PKCE/process death, verified-email policy, refresh/logout failures, second-user cache isolation, web callbacks/sessions, and legal-version changes. Staging later receives DAST, rate-limit/load abuse, mobile static/dynamic analysis, secret/key rotation, deletion/export, backup restore, alert delivery, and rollback exercises.

Before public launch, a qualified independent tester must cover API, web, mobile builds, cloud configuration, authorization, and business logic. Intrusive production testing is prohibited without approved rules of engagement. Critical/high findings block release; medium exceptions require impact, compensating control, owner, and expiry.
